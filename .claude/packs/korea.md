# korea 팩

## 이 팩도 MCP가 없다 — 그게 맞다

한국 공공데이터는 쓸만한 MCP 서버가 아직 없다.
그리고 **없어도 되는 영역**이다. 이유는 세 가지:

1. **재현성** — 수집 스크립트가 코드로 남으면 데이터가 갱신될 때 다시 돌리면 된다
2. **문서화** — 스크립트가 곧 "데이터 출처 및 수집 방법" 절이 된다
3. **검증** — "이 숫자 어디서 났냐"는 질문에 스크립트를 보여주면 끝난다

그래서 이 팩은 **`/find-data` 스킬 + 소스 목록 + API 키 안내**로 구성된다.

## 파이썬 패키지

```bash
conda run -n potato pip install requests beautifulsoup4 lxml
conda run -n potato pip install pandas openpyxl xmltodict
conda run -n potato pip install PublicDataReader
```

- `requests` + `xmltodict` — 대부분의 공공 API가 XML이나 JSON을 준다
- `beautifulsoup4` + `lxml` — API가 없어 웹에서 긁어야 할 때
- `openpyxl` — 통계청 자료는 엑셀로 오는 경우가 많다
- **`PublicDataReader`** — 국내 공공데이터 API를 파이썬으로 감싼 라이브러리.
  실거래가·KOSIS·ECOS 등을 지원한다. 있으면 편하다

지도 시각화가 필요하면:
```bash
conda run -n potato pip install geopandas folium
```

## 수집할 때 규칙

1. **원본을 그대로 저장한다.** 받은 파일을 `data/raw/`에, 가공한 것을
   `data/processed/`에. 원본을 덮어쓰면 다시 받아야 한다
2. **`sources.md`를 남긴다.** 무엇을, 언제, 어디서, 어떤 조건으로 받았는지.
   보고서 쓸 때 그대로 옮기면 된다
   ```markdown
   ## 데이터 출처
   | 데이터 | 출처 | 수집일 | 기간 | 라이선스 | 스크립트 |
   | --- | --- | --- | --- | --- | --- |
   | 아파트 실거래가 | 국토부 실거래가 API | 2026-08-06 | 2020-01~2026-06 | 이용약관 준수 | `collect_rt.py` |
   ```
3. **API 호출 간격을 지킨다.** 대부분 초당 요청 제한이 있다.
   `time.sleep(0.1)` 정도는 넣자. 막히면 키가 정지될 수도 있다
4. **이용약관을 확인한다.** 상업적 이용, 재배포 조건이 소스마다 다르다

## 감사 체크리스트

공통 체크리스트에 더해 공공데이터 특유의 것:

- [ ] **행정구역 변경** — 시군구 통폐합·명칭 변경으로 시계열이 끊기지 않았는가?
      (예: 창원시 통합, 세종시 출범)
- [ ] **통계 기준 변경** — 조사 방식이나 분류 체계가 중간에 바뀌지 않았는가?
      (산업분류 개정, 조사 표본 변경)
- [ ] **집계 단위 불일치** — 읍면동과 시군구, 행정동과 법정동을 섞지 않았는가?
- [ ] **결측의 성격** — "0"인가 "미조사"인가 "비공개"인가?
      공공데이터는 소규모 지역을 비공개 처리하는 경우가 많다
- [ ] **실거래가 특유** — 해제된 거래가 포함됐는가? 직거래와 중개거래를 구분했는가?
- [ ] **집계 시점** — 통계 공표일과 기준일이 다르다. 어느 쪽으로 붙였는가?
      (금융·시계열이면 이게 곧 룩어헤드 편향이 된다)
