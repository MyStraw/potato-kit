# industrial 팩

## 이 팩은 MCP가 없다 — 그게 맞다

산업공학은 **외부 데이터베이스를 조회하는 분야가 아니라 문제를 푸는 분야**다.
필요한 것은 데이터를 "가져오는" 도구가 아니라 "푸는" 도구다.
그래서 이 팩은 MCP 대신 **파이썬 라이브러리 + `/optimize` 스킬**로 구성된다.

데이터가 필요하면 `korea` 팩(공공데이터)이나 `ocean` 팩(관측)을 함께 켜면 된다.

## 파이썬 패키지

```bash
conda run -n potato pip install ortools simpy networkx pulp
conda run -n potato pip install scipy numpy pandas matplotlib
```

| 패키지 | 무엇에 쓰나 |
| --- | --- |
| **`ortools`** | 구글 최적화 도구. 선형·정수계획(MIP), 제약충족(CP-SAT), 차량경로(VRP), 스케줄링. **주력** |
| **`simpy`** | 이산사건 시뮬레이션. 대기행렬, 생산라인, 물류 흐름 |
| `networkx` | 네트워크 분석. 공급망, 최단경로, 최대유량 |
| `pulp` | 간단한 선형계획 모델링 (OR-Tools보다 문법이 쉽다) |
| `scipy.optimize` | 연속 최적화, 비선형 |

추가로 필요할 수 있는 것:
```bash
conda run -n potato pip install pyomo          # 대규모 수리계획 모델링
conda run -n potato pip install salabim        # 애니메이션 되는 시뮬레이션
conda run -n potato pip install deap           # 유전 알고리즘 등 메타휴리스틱
```

## 전형적인 작업 흐름 — `/optimize`

```
1. 정식화   결정변수 / 목적함수 / 제약을 말로 먼저 정리한다
            ← 여기가 제일 중요하다. 코드보다 먼저
2. 도구 선택 선형·정수면 OR-Tools MIP
            조합·스케줄링이면 CP-SAT
            시간에 따라 상태가 변하면 SimPy
            네트워크 구조면 NetworkX
3. 모델링   작은 예제로 먼저 짠다. 손으로 답을 아는 크기로
4. 확대     실제 규모로 키운다. 안 풀리면 완화·분해·휴리스틱
5. 민감도   입력이 흔들리면 답이 얼마나 바뀌나
6. 리포트   /report
```

## 감사 체크리스트

`methods-reviewer`의 **산업공학·최적화** 절이 활성화된다.

### 최적화의 실패는 대개 푸는 단계가 아니라 세우는 단계에서 일어난다

- [ ] **모델링 타당성** — 결정변수·목적함수·제약이 실제 문제와 대응하는가?
      최적해가 나왔는데 현장에서 "그건 못 한다"고 하면 제약이 빠진 것이다
- [ ] **제약 누락** — 현장에서 너무 당연해서 아무도 말 안 한 제약이 있는가?
      (교대 근무 규칙, 장비 호환성, 안전 규정, 노조 협약…)
      → 최적해를 현장 담당자에게 보여주고 "이대로 하면 되나요"를 물어보는 게
      가장 확실한 검증이다
- [ ] **목적함수의 단일성** — 실제로는 여러 목표가 충돌하는데 하나로 합쳤는가?
      가중합으로 뭉갤 때 가중치의 근거가 있는가? (파레토 분석을 고려)
- [ ] **최적해의 취약성** — 입력이 5~10% 흔들리면 답이 크게 바뀌는가?
      바뀐다면 그 최적해는 실무에서 쓸 수 없다 (강건 최적화 고려)
- [ ] **국소해** — 비볼록 문제에서 초기값을 여러 개 시도했는가?
      한 번 돌리고 "최적"이라고 부르지 않았는가?

### 시뮬레이션

- [ ] **검증(validation)** — 시뮬레이션 결과를 실제 관측치와 대조했는가?
      대조 없이 시뮬레이션 결과만으로 결론 내리지 않았는가?
- [ ] **난수 반복** — 확률적 시뮬레이션을 한 번만 돌리고 결론 내렸는가?
      → 여러 번 돌려 신뢰구간을 내야 한다
- [ ] **워밍업 구간** — 초기 과도 구간을 통계에서 제외했는가?
- [ ] **분포 가정** — 도착·서비스 시간 분포를 실제 데이터로 적합했는가,
      아니면 그냥 지수분포로 가정했는가?

## 데이터가 필요하면

산업공학 문제도 결국 데이터가 필요하다. 어디서 구하나:

| 필요한 것 | 어디서 |
| --- | --- |
| 물류·교통량 | 국가교통DB (ktdb.go.kr), 공공데이터포털 |
| 항만·물동량 | 해양수산부 PORT-MIS, 항만물류통계 |
| 제조·생산 통계 | KOSIS 광업제조업조사 |
| 도로·대중교통 | 국가교통정보센터, 카카오/네이버 지도 API |
| 기상 (운영에 영향) | 기상청 (ocean 팩) |

→ `korea` 팩을 함께 켜고 `/find-data`로 수집한다.

**공개 데이터가 없으면 현장 데이터를 받아야 한다.** 이때 `CLAUDE.md`의
데이터 보호 규칙이 적용된다 — 기업 내부 데이터는 외부로 나가면 안 된다.
로컬에서 처리하고 집계 결과만 다룬다.

## 해양과 함께 쓸 때

항만 운영, 선박 스케줄링, 양식장 관리처럼 **환경 조건이 운영에 영향을 주는**
문제라면 `ocean` 팩과 조합하는 게 자연스럽다.
관측·예측(ocean) → 의사결정(industrial)의 두 단계로 나눠서 접근하면 된다.
