# /potato-journal — 연구 여정 HTML 일지

```
/potato-journal                       ← 현재 프로젝트 전체를 일지로
/potato-journal Stage 2까지만
/potato-journal 지도교수님 보여드릴 용도로
```

## 이 스킬이 다른 스킬과 다른 점

| 스킬 | 시점 | 산출물 |
| --- | --- | --- |
| `/potato-report` | 실험이 **끝난 뒤** 한 번 | 독자용 최종 보고서 (md/PDF) |
| `/potato-study-paper` | **남의 논문**을 읽을 때 | 논문 정독 노트 HTML |
| **`/potato-journal`** | **내 연구가 진행 중일 때** 반복 | **시간순 연구일지 HTML — "내가 뭘 했고 그때 결과가 어땠더라"의 답** |

순번 로그(`로그/NN_*.md`)는 정본이지만 md 파일 수십 개를 뒤지는 건 느리다.
이 스킬은 흩어진 기록을 **브라우저에서 새로고침 한 번으로 훑는 한 페이지**로
모은다. 대화창 응답은 "일지 갱신했습니다 — 파일 경로" 한 줄이면 충분하다.

## 산출물

```
reports/journal/
├── index.html        ← 일지 본문. 재실행할 때마다 소스에서 재생성
└── style.css          ← potato-study-paper의 example/style.css 를 복사해서 시작
```

## 원천과 재생성 원칙

**일지는 2차 산출물이다.** 정본은 언제나 `plan.md`(사전등록·진행 기록),
`로그/`(순번 로그), `results.md`(동결 표)이고, 일지는 이들로부터 **매번 전체
재생성**한다 — 일지에만 손으로 고친 내용은 다음 재실행 때 사라지므로, 고칠 게
있으면 정본(md)을 고치라고 사용자에게 안내한다. 수치는 정본 파일에서 읽어 넣고,
기억이나 대화 내용으로 지어 넣지 않는다.

## 문서 구조 (위에서 아래로)

1. **헤더**: 프로젝트 한 줄 목표 (plan.md 첫 절), 마지막 갱신일, 원천 파일 링크.
2. **진행 대시보드**: 단계(Stage/실험 축)별 상태 표 — 통과/진행 중/대기,
   한 줄 결과, 근거 로그 번호. CLAUDE.md에 단계 게이트 표가 있으면 그 구조를 따른다.
3. **핵심 결과 모음**: results.md의 동결 표들을 HTML 표로 (동결 선언·각주·한계
   문구까지 그대로 — 표만 뜯어오고 단서를 떼면 왜곡이다). `reports/figs/` 그림이
   있으면 해당 절에 임베드.
4. **타임라인 (본문)**: 순번 로그를 시간순으로 한 항목씩 —
   - 제목·날짜·로그 번호 (원본 md 상대링크)
   - **무엇을/왜**: 결정과 근거 요약 (로그의 결정 절 압축)
   - **결과**: 그 시점에 나온 수치·판정 (있으면 작은 표로)
   - 실수·정정·감사 지적 같은 굴곡도 **그대로 싣는다** — 일지의 가치는 성공담이
     아니라 "왜 이 길로 왔는지"다.
5. **부록**: 환경(env yml 목록), 데이터 계보(원천→파생 경로), 용어.

sticky 목차(스테이지 → 로그 항목 2단계)를 왼쪽에 붙인다. style.css의
`panel`/`explain`/`quote` 박스를 재활용한다 (통과=panel, 실패/정정=quote 등
일관된 색 규약을 정해 문서 안에서 유지).

## 절차

1. `plan.md` → `results.md` → `로그/` 전체 목록 순으로 읽는다 (로그가 많으면
   제목만 먼저 훑고 타임라인 뼈대를 세운 뒤 내용을 채운다). `reports/figs/` 목록 확인.
2. 최초 1회: `reports/journal/` 생성, style.css 복사, index.html 뼈대 작성.
3. 타임라인·표·대시보드를 채운다. 표의 모든 수치는 정본 파일에서 복사한다.
4. 재실행 시: 전체 재생성 후, 이전 버전과 대시보드가 달라진 지점(새 통과, 새 로그)을
   대화창에 한 줄로 알려준다.
5. 브라우저로 여는 법을 안내한다: `open reports/journal/index.html`.

## 데이터 보호 (연구 데이터 프로젝트에서 중요)

- 일지에는 **집계 수치·판정·설계 결정만** 싣는다. 환자/개인 단위 레코드, 식별자
  (subject/hadm/stay ID 등), 원자료 행은 절대 넣지 않는다 — 로그 md에 실수로
  들어있더라도 일지로 옮기지 않는다.
- 일지는 로컬 HTML 파일이 기본이다. 외부 호스팅(Artifact 등)은 사용자가 명시적으로
  요청할 때만, 그리고 위 원칙 준수를 재확인한 뒤에만 한다.

## 하지 말 것

- 정본에 없는 수치를 "기억으로" 채우기 — 일지가 정본과 다르면 그게 버그다.
- 실패·정정 기록 생략 — 매끈한 일지는 거짓말이다.
- 대화창에 일지 전문 쏟아붓기 — 파일에 쓰고 경로만 알린다.
