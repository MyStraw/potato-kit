# /potato-log — 연구 여정 HTML 로그

```
/potato-log                       ← 현재 프로젝트 전체를 연구로그로
/potato-log Stage 2까지만
/potato-log 지도교수님 보여드릴 용도로
```

## 이 스킬이 다른 스킬과 다른 점

| 스킬 | 시점 | 산출물 |
| --- | --- | --- |
| `/potato-report` | 실험이 **끝난 뒤** 한 번 | 독자용 최종 보고서 (md/PDF) |
| `/potato-study-paper` | **남의 논문**을 읽을 때 | 논문 정독 노트 HTML |
| **`/potato-log`** | **내 연구가 진행 중일 때** 반복 | **시간순 연구로그 HTML — "내가 뭘 했고 그때 결과가 어땠더라"의 답** |

순번 로그(`로그/NN_*.md`)는 정본이지만 md 파일 수십 개를 뒤지는 건 느리다.
이 스킬은 흩어진 기록을 **브라우저에서 새로고침 한 번으로 훑는 한 페이지**로
모은다. 대화창 응답은 "연구로그 갱신했습니다 — 파일 경로" 한 줄이면 충분하다.

## 산출물

```
reports/log/
├── index.html        ← 본문. 재실행할 때마다 소스에서 재생성
└── style.css          ← potato-study-paper의 example/style.css 복사 + 아래 로그 전용 클래스 추가
```

## 레이아웃 (중요 — 어기면 목차가 뜨지 않는다)

potato-study-paper 템플릿과 같은 구조를 **그대로** 쓴다:

```html
<body>
<div class="layout">            ← 이 래퍼가 없으면 sticky 목차가 동작하지 않는다
  <nav id="toc"> …목차… </nav>   ← 왼쪽 고정(sticky). 스테이지→항목 2단
  <main> …본문… </main>
</div>
</body>
```

- 목차 항목에는 study-paper의 상태 클래스를 재활용한다:
  `status-done`(통과/동결) / `status-next`(진행 중) / `status-todo`(대기).
- style.css에 로그 전용 클래스를 추가해서 쓴다 (예시 — 프로젝트에 맞게 조정):
  - `.dash-grid` 진행 대시보드 카드 그리드, 카드마다 스테이지 색 배지
  - `.tl` 타임라인: 왼쪽 세로선 + 점(●), 항목별 스테이지 색
  - `.verdict-pass`/`.verdict-fail`/`.verdict-wait` 판정 배지 (초록/주황/회색)
- 표는 `<div class="table-wrap">`(overflow-x:auto)로 감싼다 — 좁은 화면 대비.

## 원천과 재생성 원칙

**연구로그는 2차 산출물이다.** 정본은 언제나 `plan.md`(사전등록·진행 기록),
`로그/`(순번 로그), `results.md`(동결 표)이고, 이 문서는 이들로부터 **매번 전체
재생성**한다 — 여기만 손으로 고친 내용은 다음 재실행 때 사라지므로, 고칠 게
있으면 정본(md)을 고치라고 사용자에게 안내한다. 수치는 정본 파일에서 읽어 넣고,
기억이나 대화 내용으로 지어 넣지 않는다.

## 문서 구조 (위에서 아래로)

1. **헤더**(`page-head`): 프로젝트 한 줄 목표 (plan.md 첫 절), `updated-badge`로
   마지막 갱신일, 정본 파일 안내.
2. **진행 대시보드**: 단계(Stage/실험 축)별 상태 — 통과/진행 중/대기 배지,
   한 줄 결과, 근거 로그 번호. CLAUDE.md에 단계 게이트 표가 있으면 그 구조를 따른다.
   바로 아래에 "지금까지의 이야기 (세 문장)" `explain` 박스 — 처음 여는 사람용 요약.
3. **핵심 결과 모음**: results.md의 동결 표들을 HTML 표로 (동결 선언·각주·한계
   문구까지 그대로 — 표만 뜯어오고 단서를 떼면 왜곡이다). `reports/figs/` 그림이
   있으면 해당 절에 임베드.
4. **타임라인 (본문)**: 순번 로그를 시간순으로 한 항목씩 —
   - 제목·날짜·로그 번호 (원본 md 상대링크)
   - **무엇을/왜**: 결정과 근거 요약 (로그의 결정 절 압축)
   - **결과**: 그 시점에 나온 수치·판정 (있으면 작은 표로)
   - 실수·정정·감사 지적 같은 굴곡도 **그대로 싣는다** — 로그의 가치는 성공담이
     아니라 "왜 이 길로 왔는지"다.
5. **부록**: 환경(env yml 목록), 데이터 계보(원천→파생 경로), 용어.

## 절차

1. `plan.md` → `results.md` → `로그/` 전체 목록 순으로 읽는다 (로그가 많으면
   제목만 먼저 훑고 타임라인 뼈대를 세운 뒤 내용을 채운다). `reports/figs/` 목록 확인.
2. 최초 1회: `reports/log/` 생성, style.css 복사+로그 전용 클래스 추가, index.html 작성.
3. 타임라인·표·대시보드를 채운다. 표의 모든 수치는 정본 파일에서 복사한다.
4. 재실행 시: 전체 재생성 후, 이전 버전과 대시보드가 달라진 지점(새 통과, 새 로그)을
   대화창에 한 줄로 알려준다.
5. 브라우저로 여는 법을 안내한다: `open reports/log/index.html`.

## 데이터 보호 (연구 데이터 프로젝트에서 중요)

- 연구로그에는 **집계 수치·판정·설계 결정만** 싣는다. 환자/개인 단위 레코드, 식별자
  (subject/hadm/stay ID 등), 원자료 행은 절대 넣지 않는다 — 순번 로그 md에 실수로
  들어있더라도 이 문서로 옮기지 않는다.
- 로컬 HTML 파일이 기본이다. 외부 호스팅(Artifact 등)은 사용자가 명시적으로
  요청할 때만, 그리고 위 원칙 준수를 재확인한 뒤에만 한다.

## 하지 말 것

- 정본에 없는 수치를 "기억으로" 채우기 — 로그가 정본과 다르면 그게 버그다.
- 실패·정정 기록 생략 — 매끈한 연구로그는 거짓말이다.
- 대화창에 전문 쏟아붓기 — 파일에 쓰고 경로만 알린다.
- `.layout` 래퍼 생략 — 목차가 본문 위에 얹혀 못생겨진다 (초판 실수에서 배운 것).
