# /potato-research — 연구 한 사이클 (반자동)

```
/potato-research 부산 청년 주거 실태
/potato-research 이 논문 우리 데이터에 적용해보고 싶어
/potato-research data/train.csv 로 생존 예측
/potato-research                    ← 뭘 할지 모르겠을 때. 물어봐 준다
```

**반자동이다.** 단계를 알아서 이어가되 **매 단계 끝에서 멈추고 물어본다.**
연구는 중간에 방향이 바뀌는 게 정상이고, 혼자 끝까지 달리면 잘못된 방향으로
한도만 태운다.

---

## 0. 진입 유형을 먼저 가른다

**이게 이 스킬의 핵심이다.** 유형에 따라 완전히 다른 경로를 탄다.
사용자 말에서 판별되면 확인만 받고, 애매하면 물어본다.

```
어떤 상황인지 먼저 확인할게요.

  A. 논문·방법이 있고, 그걸 내 데이터에 적용하거나 확장하고 싶다
     → 논문 재현 → 어댑터 → 확장 실험
  B. 데이터가 있고, 그걸로 예측하거나 설명하고 싶다
     → 탐색 → 실험 → 감사 → 보고
  C. 주제만 있고 데이터도 문제도 아직 흐릿하다
     → 문제 쪼개기 → 데이터 발굴 → 탐색 → 분석
  D. 무엇을 어떻게 할지 결정하는 문제다 (스케줄·배치·경로)
     → 정식화 → 최적화 → 민감도 분석

어느 쪽인가요?
```

**판별 힌트**

| 사용자가 이렇게 말하면 | 유형 |
| --- | --- |
| 논문 제목·arXiv·DOI·깃허브 링크가 나온다 | **A** |
| 파일 경로가 나온다, "예측", "분류", "이 데이터로" | **B** |
| 주제·현상만 나온다, "실태", "요인", "관계" | **C** |
| "최적", "배치", "스케줄", "경로", "몇 개면" | **D** |

---

## 1. 계획을 세워 보여주고 승인받는다

유형이 정해지면 **전체 계획을 먼저 제시한다.** 바로 실행하지 않는다.

```markdown
## 계획 — C유형 (데이터부터 찾기)

1. 문제 쪼개기      주제를 데이터로 답할 수 있는 질문으로     (대화)
2. /potato-find-data       공개 데이터 발굴 → 수집 스크립트         (10~30분)
3. /potato-eda             탐색 + HTML 리포트                      (5분)
4. /potato-experiment      분석·모델링 + 방법론 감사               (10~40분)
5. /potato-report          보고서 (md). PDF·PPTX 는 물어본 뒤       (5분)

각 단계가 끝나면 결과를 보여드리고 계속할지 물어봅니다.
언제든 멈추거나 방향을 바꿀 수 있습니다.

시작할까요?
```

**시간 추정은 대략으로만.** 정확한 척하지 않는다.

프로젝트가 초기화되어 있지 않으면(`CLAUDE.md`가 없으면) 여기서 `/potato-start`를 먼저 돌린다.

---

## 2. 단계별 실행 — 게이트를 지킨다

각 단계는 **해당 스킬에 위임한다.** 여기서 다시 구현하지 않는다.

### 게이트 형식 (매 단계 끝)

```markdown
## [2/5] 데이터 수집 완료

**한 일**: KOSIS·국토부에서 3개 데이터셋 수집 (수집 스크립트 3개 남김)
**결과**: 실거래가 184,332건, 연령별 인구 4,120행, 사업체 통계 2,890행
**막힌 것**: 청년 전월세 부담률은 직접 제공하는 통계가 없음
             → 실거래가 + 소득으로 계산해야 함

다음은 [3/5] 탐색(/potato-eda)입니다.

  1. 계속 진행
  2. 방향을 바꾸고 싶다 (무엇을?)
  3. 여기서 멈춘다
```

**세 가지를 반드시 보고한다**: 한 일 / 결과 / **막힌 것**.
막힌 것을 숨기면 다음 단계에서 더 크게 터진다.

### 게이트를 건너뛰어도 되는 경우

사용자가 처음부터 `"확인 안 물어보고 끝까지 가줘"`라고 하면 게이트를 생략한다.
단 **다음 셋은 생략하지 않는다** — 되돌리기 어렵기 때문이다:

- 방법론 감사에서 **major** 판정이 나왔을 때
- 데이터 반출 제한이 걸린 데이터를 다루게 됐을 때
- 시스템 변경(패키지 설치, 환경 생성)이 필요할 때

## 3. 유형별 경로

### A. 논문 베이스라인 → 아이디어 확장

```
1. /potato-lit-review <논문 주제>     선행·후속 지형 파악          [게이트]
2. /potato-reproduce <논문>           저자 코드 재현 → 수치 대조    [게이트]
   └ 원 논문 수치와 안 맞으면 원인 규명하고 넘어간다
3. 데이터 차이 분석            내 데이터 vs 논문 데이터      [게이트]
4. /potato-experiment                 원 방법 vs 내 아이디어 (ablation)
   └ 변경점 하나씩. 한 번에 여러 개 바꾸지 않는다
5. /potato-report
```

**2번에서 자주 멈춘다.** 환경 구성이 안 되거나 수치가 안 맞으면
거기서 게이트를 걸고 사용자와 상의한다. 억지로 진행하지 않는다.

### B. 데이터 있음 → 예측·설명

```
1. /potato-eda <파일>                 성격 파악 + 리포트            [게이트]
   └ 여기서 "이 데이터로 풀 수 있는 문제 3가지"를 제안한다
2. 문제 확정                   무엇을 예측/설명할지          [게이트]
3. /potato-experiment                 베이스라인 → 모델 비교 → 감사  [게이트]
   └ 감사에서 major 나오면 반드시 멈춘다
4. /potato-report
   └ 경진대회면 /potato-submit 도
```

### C. 주제만 있음 → 데이터부터

```
1. 문제 쪼개기                 데이터로 답할 질문 3~5개      [게이트]
   └ 각 질문마다 "어떤 데이터가 있어야 답하나"를 함께
2. /potato-find-data <고른 질문>      소스 탐색 → 실현가능성 → 수집  [게이트]
   └ 못 구하면 여기서 질문을 바꾼다. 정상이다
3. /potato-eda                        받은 게 쓸만한지              [게이트]
4. /potato-experiment 또는 기술통계
   └ 예측 모델이 필요 없는 과제도 많다. 판단해서 제안한다
5. /potato-report
```

**2번에서 질문이 바뀌는 것은 실패가 아니다.** `plan.md`에 바뀐 이유를 적는다.

### D. 결정 문제 → 최적화

```
1. 정식화                      결정변수·목적함수·제약        [게이트]
   └ 여기가 제일 중요하다. 말로 정리하고 사용자 확인
2. 용량 회계                   총량이 애초에 가능한가        [게이트]
   └ 부족하면 자원을 늘려야 한다. 솔버로 안 된다
3. /potato-optimize                   작은 예제 → 실제 규모
4. 민감도 분석                 입력이 흔들리면?
5. /potato-report
```

## 4. 상태를 남긴다 — 중단·재개 가능하게

매 단계 후 `plan.md`의 진행 기록에 한 줄 추가한다.

```markdown
## 진행 기록
- 2026-08-07: /potato-research 시작 (C유형). 질문 3개로 쪼갬
- 2026-08-07: [2/5] 데이터 수집 — 3개 확보, 부담률은 계산 필요
- 2026-08-07: [3/5] EDA — 2023년 행정동 개편으로 시계열 끊김 발견
```

세션이 끊겨도 다음에 `plan.md`를 읽고 이어갈 수 있어야 한다.
`/potato-research 이어서` 라고 하면 진행 기록을 읽고 다음 단계부터 시작한다.

---

## 5. 한도 관리 (Pro 구독)

전 과정을 한 번에 돌리면 한도를 크게 쓴다. 다음을 지킨다.

- **병렬 서브에이전트는 3개까지.** `/potato-experiment`가 더 쓰려 하면 순차로 돌린다
- **긴 단계 전에 미리 알린다**: "이 단계는 시간과 한도를 좀 씁니다. 진행할까요?"
- **한도가 임박했다는 신호가 보이면** 게이트에서 우선순위를 제안한다:
  결과 생성 > 정리 > 탐색
- 사용자가 급하다고 하면 `/potato-eda`·`/potato-experiment`를 축약 모드로 (베이스라인 + 모델 하나)

---

## 6. 하지 않는 것

- **게이트 없이 끝까지 달리기** (명시적으로 요청받은 경우 제외)
- **막힌 것을 숨기고 다음 단계로 넘어가기**
- 감사에서 major가 나왔는데 그냥 진행하기
- 사용자가 "멈춘다"를 골랐는데 "그래도 이것만" 하고 계속하기
- 유형 판별을 건너뛰고 아무 경로나 타기 — 유형이 틀리면 전부 헛수고다
