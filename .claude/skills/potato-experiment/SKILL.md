# /potato-experiment — 실험 한 사이클

전처리 → 모델 비교 → **감사** → 종합. 감사가 이 스킬의 핵심이다.
점수를 올리는 것보다 **틀린 결과를 내지 않는 것**이 먼저다.

```
/potato-experiment
/potato-experiment 시계열이야. 워크포워드로 검증해줘
/potato-experiment 빠르게. 해커톤 중이라 시간 없어
```

## 절차

### 0. 준비 확인

- `results.md`가 있으면 읽는다 — 이미 한 것을 반복하지 않기 위해
- EDA를 안 했으면 먼저 `/potato-eda`를 권한다. 데이터를 모르고 모델부터 만들면
  대부분 시간 낭비가 된다
- 데이터 성격(일반/시계열/공간/개체반복)을 확인한다 → 검증 설계가 여기서 갈린다

### 1. 검증 설계를 먼저 정한다

**모델보다 검증이 먼저다.** 검증이 틀리면 모델 비교가 전부 무의미하다.

| 데이터 | 분할 |
| --- | --- |
| 일반 (i.i.d.) | `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` |
| **시계열** | `TimeSeriesSplit` 또는 워크포워드. **셔플 절대 금지** |
| 개체 반복측정 | **`StratifiedGroupKFold`** (같은 환자/사용자가 양쪽에 들어가면 안 됨) |
| 공간 | 공간 블록 분할 |

정한 방식과 그 이유를 한 줄로 말하고 진행한다.

> ⚠️ **`GroupKFold`가 아니라 `StratifiedGroupKFold`를 쓴다.**
> `GroupKFold`는 층화를 하지 않고 `shuffle`·`random_state`도 없다. 그래서
> (1) 폴드별 타깃 비율이 들쭉날쭉해지고, (2) 가능한 분할이 하나뿐이라 변동을 잴 수 없다.
>
> 이걸 모르고 `StratifiedKFold` 결과와 `GroupKFold` 결과를 빼면, 그 차이는
> **"그룹 누수 효과"가 아니라 "그룹 효과 + 층화 상실 + 단일 분할 노이즈"의 합**이다.
> 시운전에서 실제로 이 함정에 빠져 누수 크기를 1.5배 과대평가했다.
>
> **진단법**: `DummyClassifier(strategy="most_frequent")`의 폴드 간 표준편차를 본다.
> 모델이 아니라 폴드 구성만 반영하므로, 이 값이 두 분할에서 크게 다르면 층화가 깨진 것이다.

### 2. 전처리 — 반드시 파이프라인 안에서

```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer

pipe = Pipeline([
    ('prep', ColumnTransformer([...])),   # 폴드 안에서 fit 된다
    ('model', model),
])
```

**대치·스케일링·인코딩을 파이프라인 밖에서 전체 데이터에 적용하면 데이터 누수다.**
이건 협상 대상이 아니다. 예외는 없다.

피처 엔지니어링(파생 변수 생성)은 타깃을 쓰지 않는 한 밖에서 해도 된다.
타깃 인코딩은 반드시 폴드 안에서.

### 3. 베이스라인부터

```
1) 더미 (최빈값 / 평균)
2) 단순 선형·로지스틱 회귀
3) 그다음에 트리·부스팅
```

**복잡한 모델이 베이스라인을 못 이기면 그 사실 자체가 결과다.**
"XGBoost가 로지스틱 회귀보다 나을 게 없다"는 것도 보고할 가치가 있는 발견이다.

### 4. 모델 비교

기본 세트 (분류):
- `LogisticRegression` (스케일링 파이프라인)
- `RandomForest`
- `XGBoost` 또는 `LightGBM`

**공정하게 비교한다**: 동일 폴드, 비슷한 규모의 하이퍼파라미터 탐색.
한 모델만 열심히 튜닝하고 비교하면 그건 비교가 아니다.

> **"동일 전처리 = 공정"이 아니다.** 부스팅 계열(HistGradientBoosting, LightGBM)은
> 결측을 네이티브로 처리하고 범주형도 직접 받는다. 여기에 선형 모델용 전처리
> (결측 대치 + 원핫 + 표준화)를 강제하면 그 모델만 정보를 잃고 링에 오른다.
> 모델별로 적합한 전처리를 붙이는 쪽이 오히려 공정하다.

> **단일 시드 표에서 순위를 읽지 않는다.** 시드 하나로 나온 0.837 vs 0.829는
> 대개 우연이다. 최소 5~10회 반복(`RepeatedStratifiedKFold`)해서 **시드 간 변동**과
> 함께 보고하고, 모델 차이가 그 변동보다 작으면 **"구분되지 않음"이라고 명시한다.**
> 시운전에서 시드 42의 1위 모델이 10시드 평균에서는 꼴찌였다.
>
> 참고: `cross_validate`가 주는 `std()`는 폴드 점수의 표준편차일 뿐,
> 신뢰구간도 표준오차도 아니다(폴드끼리 훈련셋이 겹쳐 독립이 아니다).
> 이 값을 유의성 판정 임계값으로 쓰면 안 된다.

**병렬 실행**: 모델이 3개 이상이면 `data-analyst` 서브에이전트로 병렬화할 수 있다.
단 Pro 구독이면 3개를 넘기지 않는다. 급하면 순차로 돌린다.

### 5. 감사 — 생략 금지

`methods-reviewer` 서브에이전트를 호출한다.

```
methods-reviewer 로 지금까지의 전처리·검증·평가를 감사해줘.
```

켜져 있는 팩에 따라 도메인 체크리스트가 함께 적용된다
(의료 → 표본 선택 편향·결측 메커니즘, 금융 → 룩어헤드·생존편향 등).

**감사 결과가 major면 거기서 멈추고 고친다.** 점수를 더 올리는 것보다
틀린 걸 고치는 게 먼저다.

시간이 없어도(해커톤) **제출·발표 직전에 한 번은 반드시** 돌린다.
데이터 누수 하나로 실격되는 게 경진대회다.

### 6. 결과 종합

`results.md`에 기록한다:

```markdown
## 실험 — <날짜>

**설정**: Stratified 5-fold CV, seed=42, 전처리는 Pipeline 내부

| 모델 | Accuracy | ROC-AUC | 비고 |
| --- | --- | --- | --- |
| Dummy (최빈값) | 0.616 | 0.500 | 베이스라인 |
| LogisticRegression | 0.8126 ± 0.0183 | 0.8611 ± 0.0177 | |
| RandomForest | 0.8350 ± 0.0086 | 0.8737 ± 0.0193 | n=300, depth=6 |
| XGBoost | **0.8440 ± 0.0181** | **0.8841 ± 0.0216** | lr=0.03, depth=6 |

**해석**
- XGB − RF = +0.0090 → 폴드 편차(±0.018) 안. **유의한 차이로 보기 어렵다**
- XGB − LogReg = +0.0314 → 편차를 넘음. 트리 계열의 이득은 실질적이다
- 즉 이득의 대부분은 "부스팅 vs 배깅"이 아니라 **선형 → 트리 전환**에서 온다

**감사** (methods-reviewer): warn
- minor: CV 내부 대치 누수 — age_ref를 분할 전에 계산. 절대 점수는 약간 낙관적
- minor: 비-nested CV — 하이퍼파라미터를 고른 폴드로 재평가. 상대 비교는 유효

**실패한 시도**
- SMOTE 적용 → 성능 변화 없음 (0.842). 불균형이 심하지 않아서인 듯

**스크립트**: `train_compare.py`
```

**표준편차를 반드시 함께 적는다.** 평균만 적으면 과장이 된다.
차이가 편차 안이면 "차이 있다"고 쓰지 않는다.
