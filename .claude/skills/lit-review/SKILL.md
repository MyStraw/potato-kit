# /lit-review — 문헌 조사

```
/lit-review 아스피린 약물상호작용
/lit-review 시계열 이상탐지 딥러닝. 최근 3년 위주로
/lit-review 청년 주거이동 결정요인. 국내 논문도 포함해서
```

## 절차

### 1. 질문을 좁힌다

"딥러닝 의료 적용"은 조사할 수 없다. 다음을 정한다:
- **무엇을** 예측/설명하려는가
- **어떤 데이터로**
- **어떤 제약에서** (실시간? 해석 가능성 필요? 데이터 규모?)

요청이 넓으면 **좁힌 버전을 제안하고 진행한다.** 되묻기만 하고 멈추지 않는다.

### 2. `literature-scout` 서브에이전트에 위임

넓은 조사는 서브에이전트가 맡는다. 컨텍스트를 아끼고 병렬 검색이 가능하다.
논문 한 편 확인 같은 좁은 일은 직접 한다.

### 3. 도구 사용 순서

1. **`paper-search`** — 기본. arXiv·PubMed 검색
2. **`biomcp`** (medical 팩) — 유전자·질환·변이·약물 이름으로 정밀 검색.
   임상시험(ClinicalTrials.gov)과 OpenFDA도 여기서
3. **OpenAlex/`pyalex`** (libsci 팩) — 인용 관계, 대량 메타데이터
4. **WebSearch** — MCP로 안 잡히는 것. 최신 프리프린트, 기술 보고서, 블로그

**국내 문헌이 필요하면** RISS·KCI·DBpia를 WebSearch로 함께 찾는다.
한국어 주제(정책, 지역, 국내 산업)는 국제 DB에 거의 없다.

### 4. 검색 전략

- **동의어를 여러 갈래로.** 같은 개념의 다른 이름, 축약어, 분야별 용어.
  한 검색어 결과만 보면 편향된다
- **서베이 논문을 먼저 찾는다.** 지형도를 빨리 얻는 가장 싼 방법이다
- **핵심 논문에서 확장한다.** 참고문헌(뒤로) + 피인용(앞으로)
- **반대 증거를 일부러 찾는다.** 사용자 가설에 유리한 것만 모으지 않는다

### 5. 정리

`notes/lit-<주제>.md`로 저장한다. 형식은 `literature-scout` 에이전트 정의 참조.
핵심은:

- 한 문단 요약 (이 분야가 어디까지 왔고 무엇이 미해결인가)
- 핵심 논문별: 주장 / 방법 / 결과 / 한계 / **우리에게 어떻게 쓸 수 있나**
- 시간순 흐름
- **연구 공백** + 왜 아직 안 됐는지에 대한 추정
- 우리 프로젝트에 대한 제안
- **확인하지 못한 것** (접근 불가, 초록만 본 것)

## 절대 규칙

- **존재하지 않는 논문을 만들어내지 않는다.** DOI·PMID는 실제 조회된 것만 적는다
- **읽지 않은 것을 읽은 것처럼 쓰지 않는다.** 초록만 봤으면 그렇게 적는다
- 인용 수·연도는 조회된 값만. 추정이면 추정이라고 밝힌다

문헌 조사에서 지어낸 인용 하나가 논문 전체의 신뢰를 무너뜨린다.
모르면 "찾지 못했다"고 쓰는 게 정답이다.

## 용도별 변형

**해커톤 근거 확보용** (30분)
→ 서베이 1편 + 핵심 논문 3편. "이 접근이 타당한 이유"만 확보하면 된다

**연구 공백 탐색용** (깊이)
→ 5년치 흐름 + 인용 네트워크. `libsci` 팩이 있으면 정량 분석까지

**방법론 검증용**
→ "이 방법을 이 데이터에 쓴 선례가 있나"에 집중.
   없다면 그것도 답이다 (기여점이 되거나, 안 되는 이유가 있거나)
