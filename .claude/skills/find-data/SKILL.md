# /find-data — 데이터 발굴·수집

```
/find-data 부산 청년 주거 실태
/find-data 아파트 실거래가. 부산 2020년 이후
/find-data 해수온 관측 자료
```

## 이 스킬의 원칙

**손으로 다운로드받게 하지 않는다. 수집 스크립트를 만든다.** 이유는 셋:

1. 데이터가 갱신되면 다시 돌리면 된다
2. 보고서의 "데이터 출처 및 수집 방법" 절이 저절로 채워진다
3. "이 숫자 어디서 났냐"는 질문에 스크립트를 보여주면 끝난다

## 절차

### 1. 질문을 데이터 요구사항으로 번역

"청년 정주여건"으로는 검색할 수 없다. 먼저 쪼갠다:

```
청년 정주여건
├─ 주거비 부담 → 실거래가, 전월세, 소득
├─ 일자리 접근성 → 사업체 통계, 통근 시간
├─ 생활 인프라 → 상권, 의료시설, 교육시설
└─ 인구 이동 → 전입·전출, 연령별 인구
```

각 갈래마다 "어떤 데이터가 있어야 답할 수 있는가"를 정한다.
**요청이 넓으면 쪼갠 결과를 보여주고 어디부터 할지 물어본다.**

### 2. 소스 탐색

**켜져 있는 팩의 "데이터 소스 메모"를 먼저 본다.**
`korea` 팩이 켜져 있으면 국내 소스 목록이, `ocean` 팩이면 해양 소스가 거기 있다.

없으면 WebSearch로 찾는다. 확인할 것:
- API가 있는가, 파일 다운로드만 되는가, 웹에서 긁어야 하는가
- API 키가 필요한가, 무료인가, 승인에 시간이 걸리는가
- 이용약관 (재배포·상업적 이용 조건)
- 갱신 주기, 제공 기간
- **집계 단위** (전국/시도/시군구/읍면동) — 필요한 해상도가 나오는가

### 3. 실현 가능성 확인 — 스크립트 짜기 전에

**받을 수 있는지 먼저 확인한다.** 작은 요청 하나를 실제로 보내본다.

```python
# 1건만 받아보고 구조 확인
resp = requests.get(url, params={..., 'numOfRows': 1})
print(resp.status_code, resp.text[:500])
```

여기서 막히면(키 미승인, 파라미터 오류, 서비스 중단) 스크립트를 다 짜기 전에
알 수 있다. 사용자에게 키 발급을 요청해야 하면 여기서 멈추고 URL을 안내한다.

**지킬 것**
- API 키는 `.env`에서 읽는다. 코드에 절대 쓰지 않는다
- 호출 간격을 둔다 (`time.sleep`). 막히면 키가 정지될 수 있다
- 페이지네이션을 처리한다. 첫 페이지만 받고 끝내지 않는다
- 실패 시 재시도 + 어디까지 받았는지 기록 (중간에 끊겨도 이어받게)
- 원본은 `data/raw/`에 그대로. 가공은 `data/processed/`에 따로

### 5. 정제

원본을 받은 뒤 별도 스크립트로 정제한다. 원본을 덮어쓰지 않는다.

흔히 필요한 것:
- 인코딩 (국내 공공데이터는 EUC-KR인 경우가 많다 → `encoding='cp949'`)
- 컬럼명 정리 (한글 컬럼명, 공백, 특수문자)
- 결측 표기 통일 ('-', '.', 'N/A', 공백 → NaN)
- 숫자 컬럼의 쉼표 제거 (`'1,234'` → `1234`)
- **행정구역 코드 통일** — 시군구 통폐합·명칭 변경 확인

### 6. `sources.md` 기록 — 빠뜨리지 않는다

```markdown
| 아파트 실거래가 | 국토부 실거래가 API | 2026-08-06 | 2020-01~2026-06 | 시군구 | 이용약관 준수 | `collect_rt.py` |

- 실거래가: 2021년 이후 해제 거래 정보가 별도 제공됨. 현재는 미반영
```


## 데이터를 못 찾았을 때

없다고 말하는 것도 결과다. 대신 대안을 제시한다:

- **대리 변수(proxy)** — 직접 지표가 없으면 근사할 수 있는 것
- **다른 집계 단위** — 읍면동이 없으면 시군구로
- **다른 기간** — 최근 데이터가 없으면 시차를 두고
- **결합** — 두 데이터를 합쳐서 원하는 지표를 계산
- **신청** — MDIS 마이크로데이터처럼 신청하면 받을 수 있는 것

## 질문이 바뀌는 것은 정상이다

데이터를 열어보고 나서 질문이 바뀌는 건 실패가 아니다.
`plan.md`에 **바뀐 이유를 적어둔다.** 그 자체가 보고서의 좋은 재료가 된다
("당초 X를 보려 했으나 데이터 제약으로 Y로 조정").
